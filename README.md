# IT Inventory QR

MVP веб-приложения для командного проекта по учету IT-инвентаря с QR-метками.

## Структура проекта

| Папка | Что внутри |
| --- | --- |
| `frontend/` | HTML, CSS и JavaScript. Показывает экраны и обращается к API. |
| `frontend/js/` | `app.js` управляет экранами, `inventory-api.js` отправляет запросы, `qr-scanner.js` читает метки. |
| `frontend/vendor/` | Библиотеки генерации и чтения QR. jsQR 1.4.0 поставляется с лицензией Apache 2.0. |
| `backend/app/` | FastAPI, модели базы и маршруты API в `routers/`. |
| `backend/tests/` | Автоматические проверки API. |

Frontend и backend разделены по папкам и общаются по HTTP. При обычном запуске FastAPI также раздаёт готовый интерфейс из `frontend/`, поэтому достаточно одного адреса и одного терминала. Документация API: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs).

## Что уже есть

- панель с метриками;
- реестр техники с поиском и фильтрами;
- карточка устройства с QR-кодом, амортизацией, ремонтами и перемещениями;
- добавление и редактирование техники;
- пакетная печать QR-меток;
- мобильный режим инвентаризации с фиксацией расхождений;
- отчеты «где что» и «что списывать»;
- импорт CSV, подготовленный из Excel или вставленный из таблицы;
- общий реестр через API: карточки и CSV-импорт сохраняются в базу;
- серверный журнал перемещений, ремонты и сохранённые результаты инвентаризации;
- QR-ссылки на паспорта и чтение меток с камеры или по фото;
- автономный деморежим с сохранением в `localStorage`.

## Как запустить

Если обновляетесь с этапа 3, остановите старый сервер (`Ctrl+C`), распакуйте
новый архив в отдельную папку и перенесите **копию** старого
`backend/inventory.db` в новый `backend/`. Сделайте это до первого запуска
новой версии. Если файла базы нет, этот шаг пропустите. Сервер добавит таблицу
QR-меток и назначит метки уже существующим устройствам.

### Общий реестр: Python + SQLite

Из корня проекта в терминале VS Code на Windows:

```powershell
cd backend
py -m pip install -r requirements.txt
py -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

На Linux/macOS используйте `python3` вместо `py`. Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Сервер раздает и интерфейс, и API. Отдельный HTTP-сервер для этого режима не нужен.

Реестр по умолчанию пуст. Добавьте устройство или загрузите пример в разделе «Импорт», затем откройте тот же адрес в другом браузере. Для загрузки изменений без перезагрузки страницы нажмите «Обновить реестр». SQLite хранит данные в `backend/inventory.db` при запуске из `backend`. Старые записи из деморежима не импортируются автоматически.

При наличии Docker можно вместо SQLite использовать PostgreSQL: задайте `POSTGRES_PASSWORD` в локальном `.env` (не коммитьте его), выполните `docker compose up --build` из корня и откройте тот же адрес.

Серверный режим пока локальный: авторизации нет, поэтому не выставляйте API в интернет.

### Этап 3: история и инвентаризация

После обновления остановите и снова запустите сервер из той же папки `backend`. Существующий `inventory.db` не удаляйте: сервер создаст недостающие таблицы при старте.

1. Откройте карточку техники и отредактируйте локацию. В истории появится запись со старым и новым помещением. Устройства с историей можно списать вместо удаления.
2. В карточке введите описание неисправности и нажмите «Открыть ремонт». Затем нажмите «Закрыть ремонт». Журнал ремонта не меняет учётный статус техники: при необходимости измените его в карточке отдельно.
3. В «Инвентаризации» выберите помещение, отметьте найденную технику и добавьте название предмета без QR. Нажмите «Завершить и сохранить». Сервер сверит данные с текущим реестром. Готовый отчёт появится в «Сохранённых проверках» и не изменится при последующих перемещениях. Черновик до сохранения остаётся в текущей вкладке.

### Демо без бэкенда

Для локального демо выполните из корня:

```powershell
py -m http.server 4173 --directory frontend
```

На Linux/macOS используйте `python3`. Затем откройте:

```text
http://localhost:4173
```

### Этап 4: проверка QR

1. Запустите сервер. Откройте «Реестр» → нажмите на строку устройства → нажмите «Ссылка на паспорт». В новом адресе откроется его карточка. QR в карточке и на печатной метке содержат ту же ссылку.
2. В «QR метки» отметьте нужные устройства и нажмите кнопку печати. После смены инвентарного номера или кабинета QR-ссылка останется действительной. Старые метки остаются пригодны для сверки, но для открытия паспорта их нужно перепечатать.
3. В «Инвентаризации» выберите помещение. На компьютере с камерой откройте локальный адрес и нажмите «Камера». После чтения метки камера выключится, а устройство отметится в сверке. Можно также нажать «Загрузить фото» или ввести номер вручную. Фото обрабатывается в браузере и не отправляется на сервер.

#### Проверка с телефона в одной сети

1. Подключите компьютер и телефон к одной доверенной сети Wi-Fi. Остановите сервер и из `backend` запустите `py -m uvicorn app.main:app --host 0.0.0.0 --port 8000`. Не перенаправляйте порт из интернета: пока в приложении нет авторизации.
2. В другом терминале выполните `ipconfig` и найдите IPv4-адрес Wi-Fi компьютера. На телефоне и на компьютере откройте `http://IPv4-АДРЕС:8000/`, например `http://192.168.1.20:8000/`. Не используйте `127.0.0.1` при печати меток для телефона: на телефоне этот адрес указывает на сам телефон. Метки содержат адрес, с которого их напечатали.
3. Напечатайте метку с сетевого адреса и отсканируйте её обычным приложением камеры телефона, чтобы открыть паспорт. Для сверки на сайте по обычному HTTP используйте «Снять фото» (если телефон предлагает камеру) или «Загрузить фото». Для прямой камеры внутри сайта с телефона нужен HTTPS с доверенным сертификатом.
