# Этап 1. FastAPI + PostgreSQL

Этот архив — **дополнительные файлы** для проекта `gnutel3/IT-inventory-tracking-with-QR-codes`. Существующие `index.html`, `app.js`, `styles.css`, `qrcode-browser.js`, `README.md` **не удалять и не заменять**.

## Шаг 1 — подготовить компьютер

Установите Git и Docker Desktop. В Docker Desktop запустите движок контейнеров.

Откройте терминал (PowerShell на Windows, Terminal на macOS/Linux).

## Шаг 2 — скачать ваш проект

```bash
git clone https://github.com/gnutel3/IT-inventory-tracking-with-QR-codes.git
cd IT-inventory-tracking-with-QR-codes
```

Если проект уже скачан, откройте именно его папку и выполните `git pull` перед внесением изменений (предварительно сохраните незакоммиченные изменения).

## Шаг 3 — добавить файлы

Распакуйте содержимое ZIP **в корень проекта**, рядом с `index.html`. Появятся `backend/`, `docker-compose.yml`, `.env.example`, `.gitignore`, `ИНСТРУКЦИЯ_ЭТАП_1.md`.

НЕ кладите папку `it-inventory-stage1` целиком внутрь репозитория — копируйте только ее содержимое.

## Шаг 4 — создать `.env`

В корне проекта скопируйте `.env.example` в `.env` и придумайте пароль:

Windows PowerShell:
```powershell
Copy-Item .env.example .env
```

macOS/Linux:
```bash
cp .env.example .env
```

Откройте `.env` и замените `replace-with-a-long-random-password` на свой длинный случайный пароль из латинских букв и цифр. **Не загружайте `.env` в GitHub!**

## Шаг 5 — запустить backend + PostgreSQL

В корне проекта:

```bash
docker compose up --build -d
```

Первый запуск может занять время, так как Docker скачивает образы и устанавливает зависимости.

Проверка:
- http://localhost:8000/health — `{"status":"ok","service":"it-inventory-backend"}`
- http://localhost:8000/docs — Swagger с доступными API-методами.

Если запуск не удался:
```bash
docker compose ps
docker compose logs backend
docker compose logs db
```

## Шаг 6 — добавить первое устройство через Swagger

1. Откройте `http://localhost:8000/docs`.
2. Найдите `POST /api/v1/categories` → Try it out → введите `{"name":"Монитор"}` → Execute.
3. Найдите `POST /api/v1/locations` → создайте `{"name":"312"}`.
4. Найдите `POST /api/v1/devices` → Try it out → введите:

```json
{
  "inventory_number": "INV-001",
  "name": "Dell P2422H",
  "manufacturer": "Dell",
  "model": "P2422H",
  "category_id": 1,
  "location_id": 1,
  "status": "IN_USE"
}
```

Если создавали другие категории/помещения ранее, используйте реальные `id` из ответов API. Нажмите Execute. Ожидается `201 Created`.

5. Откройте `GET /api/v1/devices` → Execute. В списке появится устройство.
6. Перезапустите контейнеры `docker compose restart`, обновите GET — устройство сохранится.

## Шаг 7 — проверить старый интерфейс

В **другом терминале**, из корня проекта:

```bash
python -m http.server 4173
```

Если команда `python` не найдена, попробуйте `python3` (macOS/Linux) или `py` (Windows).

Откройте http://localhost:4173 — прежний сайт должен открываться. **Пока сайт по-прежнему использует localStorage.** Подключение frontend к API — следующий этап.

## Шаг 8 — отправить изменения на GitHub

```bash
git status
git add backend docker-compose.yml .env.example .gitignore ИНСТРУКЦИЯ_ЭТАП_1.md
git commit -m "Add FastAPI backend and PostgreSQL setup"
git push origin main
```

На Windows в некоторых терминалах ввод кириллического имени может отличаться; используйте `git add -A` после проверки, что `.env` не попадает в индекс (`git status`).

**Нельзя коммитить `.env` и реальные пароли.** Если пароль всё же был опубликован, замените его.

## Результат этапа 1

Есть работающий backend `/health`, автоматическое создание таблиц, PostgreSQL с постоянным томом, справочники категорий/помещений, CRUD устройств, Swagger UI. Существующий сайт не изменен; авторизации, перемещений, реальной инвентаризации в backend и интеграции с frontend пока нет.

## Полезные команды

```bash
docker compose ps                 # состояние контейнеров
docker compose logs -f backend    # логи сервера
docker compose down               # остановить сервисы, данные сохранятся
docker compose up -d             # запустить снова
```

Не используйте `docker compose down -v`, если хотите сохранить устройства: эта команда удаляет том PostgreSQL.

## Запуск без Docker (опционально)

Для первоначальной проверки API можно использовать SQLite — PostgreSQL при этом не задействован.

```bash
cd backend
python -m venv .venv
# macOS/Linux: source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload
```

В этом режиме создается файл `backend/inventory.db` (он в .gitignore). Для финального проекта используйте Docker/PostgreSQL.
